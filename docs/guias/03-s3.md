# 03 — Bucket S3 y capas

## Objetivo

Revisar el bucket único del lake y comprender prefijos; la infraestructura se crea mediante Terraform, no manualmente desde consola. Use una cuenta/región aprobada y un nombre de bucket único globalmente.

## Preparación y captura guiada

1. Siga primero [acceso](01-acceso.md) y [Terraform](07-terraform.md). Inspeccione `terraform plan`; compruebe cifrado, bloqueo de acceso público, versionado, lifecycle y que solo se propone el bucket de datos previsto.
2. Después de habilitar la infraestructura, genere datos con el CLI AWS descrito en [Comprehend](04-comprehend.md); `--bucket` selecciona `S3Store`, no el directorio local.
3. En S3 → bucket del proyecto, capture bloqueo de acceso público, cifrado y versionado.
4. Inspeccione prefijos de la corrida: `bronze/source=<source>/ingestion_date=<fecha>/run_id=<id>/response.xml`; cuarentena `quarantine/run_id=<id>/`; Silver y Gold `*/snapshots/<id>/<table>/publication_date=<fecha>/part-00000.parquet`; control en `_control/`. El artefacto EC2 vive bajo `artifacts/`.
5. Correlacione cada objeto Bronze con manifiesto: corrida, fuente, URL, hora UTC, estado HTTP, hash y clave.
6. Compruebe lifecycle en la consola antes de confiar en el borrado automático; su política no sustituye revisión de versiones ni eliminación de datos.

## Estado y advertencias

S3 almacena objetos; prefijos son componentes de la clave, no directorios con semántica transaccional. Silver/Gold se preparan bajo snapshots y solo la referencia publicada define el conjunto vigente. Versionado puede conservar versiones borradas y aumentar almacenamiento. No elimine a mano la referencia `current` ni objetos del snapshot actual.

No se han creado recursos AWS como parte de la preparación documental. Las capturas anteriores son instrucciones para una sesión guiada, no evidencia existente. Para desmantelar, use exclusivamente el procedimiento Terraform después de respaldo y confirmación de propietario.


La configuración declarada bloquea ACL/políticas públicas, fuerza propiedad del bucket por el propietario, usa cifrado servidor AES-256, versionado y requiere TLS. Lifecycle aborta uploads multipart incompletos tras 1 día, expira resultados Athena y sus versiones no vigentes tras 7 días y otras versiones no vigentes tras 30 días. No expira automáticamente los objetos actuales del lake. Versionado no es respaldo permanente: las versiones no vigentes también expiran según política.
